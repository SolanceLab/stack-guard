# What it does

[← back to the README](../README.md)

1. **Finds what you run.** Code projects, their deploy configs (Cloudflare Workers/Pages, Fly.io, Vercel, Netlify, Docker), background services and tunnels on your computer, and the runtimes they use. When a host CLI is already installed and logged in, it confirms what is really live, because the repo and the running app can differ.
2. **Checks every package and MCP server**, without downloading new tools. It flags MCP servers that fetch themselves fresh on every start (`npx -y some-server` with no version), the easiest way in for a hijacked release. Packages are checked with `npm audit` / `pnpm` / `yarn` for JavaScript, and the free [OSV.dev](https://osv.dev) database for Python, Go, Rust, Ruby and PHP. Production packages are kept apart from build-only tools.
3. **Checks runtimes.** Node, Python and Postgres versions against [endoflife.date](https://endoflife.date): unsupported, or a security update available.
4. **Reads the news.** A scout agent searches the last 14 days of security news for the parts of your stack, confirms each story on the project's own advisory, and tells you whether it affects your versions.
5. **Checks whether it was used against you.** For each serious hole in something you deploy, a read-only breach checker asks whether the hole was reachable in your setup, how long it was open, whether logs exist for that window, and whether known traces are on this computer. See [Was I hit?](was-i-hit.md).
6. **Finds secrets committed to git.** It looks in the usual secret files (`.mcp.json`, `.env`, keys, `.npmrc`, `.pypirc`) that git tracks, and in older commits, and names the key to rotate. It never prints a value.
7. **Checks the tools on your computer.** `uv`, `pip`, `pipx`, `poetry`, `npm`, `pnpm`, `yarn`, plus the `certifi` copy inside each uv tool environment, are looked up like any package. `bun` and `deno` have no advisory feed and are listed under "Not checked".
8. **Lists and checks background services.** Launchd agents and daemons on macOS, user systemd units and cron on Linux, and scheduled tasks on Windows, with what listens on which port. It reads names and paths only (never a service's arguments or settings), shows how far each one is reachable (this computer only, the local network, or the internet through a cloudflared tunnel), and flags files someone else could change, programs in unrecognised places, broken virtualenvs and missing programs. It also tells you about new services since the last check. Only a known runtime is ever run, and only for `--version`.
9. **Reports** what is internet-facing first, then what only runs on your computer, then what is clean.
10. **Fixes, after your yes.** One fixer agent per project: same-major package upgrades with install scripts switched off (never `--force`), then it proves the project still passes its tests, builds, and works (website pages render, MCP servers still list their tools and refuse strangers). It also serves the project the way it is deployed (a Worker with `wrangler dev`, a Docker or Fly app from its image), because tests and a plain build can pass while the deployed runtime fails. Anything that breaks is put back. A major-version jump comes back to you as a question. A fix also waits until the fixed version has been public for 48 hours (change it with the `min_release_hours` setting or `STACK_GUARD_MIN_RELEASE_HOURS`), because hijacked releases are usually caught and pulled within that time; the fixer tells you when to run again. After fixing, stack-guard checks the project again and undoes the fix if a known malicious release (an OSV `MAL-` record, flagged MALICIOUS and shown first) came in.

**It never deploys, pushes, commits, upgrades Node/Python, or restarts services on its own.** It hands you the exact command and waits for your yes. Projects with unsaved changes are left alone.

**Good to know:** fixing runs your project's own tests and build, which run your project's code. That is normal for your own projects; for a repo you cloned from someone else, stack-guard asks first.
